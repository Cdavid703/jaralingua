## Account persistence

Dedicated module `server/basic2_adventure.py`; two small hooks after the existing oral route in `server/progress_api.py`. Uses existing verified API authentication, then resolves only registered Basic 2 accounts from the roster. Client-supplied student IDs are ignored. Teachers/admins have their own preview space. No roster, student credentials or grades are sent to clients.

SQLite: `/var/lib/jaralingua/basic2-adventure.sqlite3`, override `JARALINGUA_BASIC2_ADVENTURE_DB` for synthetic tests. Records keyed by server-resolved account and stage. Per-stage revision checks prevent silent concurrent-device overwrite; operation IDs make retries idempotent. Conflict UI offers copies of both versions and an explicit choice. Last 200 receipts retained per account.

Browser IndexedDB keeps per-account drafts, recordings and pending operations. Saves run after input, on reconnect, visibility changes and periodic retry. The page distinguishes device-only from acknowledged account saves. New-device continuation requires the previous device to have synced. Server failures and expired sessions preserve local drafts. Account changes clear the visible workspace. Generic auth form autosave is excluded with `data-jaralingua-managed-draft` to prevent competing writers.

Audio: private base64 audio in account-owned SQLite records, maximum 2 MB/120 seconds per stage. Native MediaRecorder plus upload fallback. Maximum request size is bounded by module validation; audio types and container headers checked. Audio duration is client metadata for formative practice, not trusted evidence of achievement for a grade. No student recordings are sent to any speech service.
