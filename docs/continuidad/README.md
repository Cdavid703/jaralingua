# Continuidad del proyecto Jaralingua

Estos documentos permiten iniciar conversaciones nuevas en el VPS sin perder las decisiones principales del docente. Se prepararon el 29 de septiembre de 2026 a partir del historial disponible y de documentación existente en el repositorio. No importan el historial de chats ni garantizan que todos los pedidos históricos estén implementados.

## Cómo iniciar una conversación

Abre `~/bin/start-codex-git`. Pon un nombre a la conversación con `/rename` y empieza, por ejemplo, así:

> Lee AGENTS.md, docs/continuidad/README.md y docs/continuidad/ingles-basico-2.md. Esta conversación se dedica a Inglés Básico 2. Primero dime qué está documentado y qué necesita verificación. No modifiques todavía archivos ni notas.

Para una conversación nueva usa `/new`; para volver a una guardada usa `/resume`. Los historiales son independientes, pero los archivos del proyecto son compartidos. Evita ediciones simultáneas en los mismos archivos.

## Cómo interpretar el estado

Una decisión del docente indica el comportamiento deseado. Un documento de implementación indica lo que se registró en ese momento. Ninguno equivale a una auditoría actual de producción. Al retomar, comprobar enlaces, archivos, datos y pruebas pertinentes, y señalar las diferencias.

Las notas individuales, correos, documentos de identidad, teléfonos y contraseñas se excluyen deliberadamente. Consultar fuentes privadas solo cuando la tarea actual lo autorice. Los pedidos históricos de cambiar notas o matrículas no se deben ejecutar otra vez.

## Primera revisión pendiente

Antes de reanudar desarrollo, comparar únicamente los archivos del tema solicitado entre GitHub, la copia de desarrollo y producción: se detectaron diferencias al preparar el VPS. No hay autorización para sincronizar todo, borrar archivos, recalificar o publicar pendientes de otros niveles.
